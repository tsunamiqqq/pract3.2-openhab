## 1. Проектування LoRaWAN емуляційної мережі

### 1.1 Архітектурні принципи та специфікація LoRaWAN
Розроблено емуляційну модель мережі LoRaWAN з топологією, що складається з:
1. **End Devices:** передають дані асинхронно у виділені вікна з подальшим відкриттям двох коротких вікон прийому, що забезпечує максимальну енергоефективність.
2. **Multi-Channel LoRaWAN Gateway:** приймає сигнали одночасно на трьох частотних каналах європейського діапазону **EU868** (`868.1 MHz`, `868.3 MHz`, `868.5 MHz`) та контролює дотримання регуляторного обмеження **Duty Cycle < 1%**.
3. **Network & Application Server:** відповідає за перевірку цілісності, дешифрування корисного навантаження за стандартом **AES-128** (`AppSKey`/`NwkSKey`), активацію вузлів за процедурою **OTAA** та динамічне керування швидкістю і потужністю передачі через механізм **ADR**.

### 1.2 Моделювання поширення радіосигналу та Spreading Factors
Для трьох кінцевих пристроїв реалізовано залежність між коефіцієнтом розширення спектра, дальністю зв'язку, часом перебування пакету в ефірі, рівнем сигналу, відношенням сигнал/шум та витратою заряду батареї:

## 2. Розробка Zigbee Mesh емуляції

### 2.1 Ієрархія ролей та топологія Zigbee PRO
Спроектовано комірчасту мережу на частотному каналі `15` з ідентифікатором мережі `PAN ID = 0x1A4F`, яка включає 7 вузлів трьох типів:
* **Zigbee Coordinator (1 вузол):** ініціалізує мережу, видає 16-бітні мережеві адреси, керує ключами безпеки `AES-128 NWK` та агрегує карту топології.
* **Zigbee Routers (3 вузли):** постійно живляться від мережі, ретранслюють пакети за алгоритмом **AODV** та оцінюють якість радіоканалу через метрику **LQI**.
* **Zigbee End Devices (3 сплячі вузли):** перебувають у режимі глибокого сну, періодично прокидаючись для передачі телеметрії через батьківський маршрутизатор.

### 2.2 Реалізація механізму самовідновлення
У файлі `zigbee_mesh_sim.rules` реалізовано алгоритм автоматичної перебудови маршрутів при відмові вузла:
* У штатному режимі `Router 3` та підключений до нього `ED3` передають трафік за маршрутом `Coordinator <- Router 2 <- Router 3 <- ED3`.
* При симуляції знеструмлення `Router 2` вузол `Router 3` фіксує втрату батьківського вузла, ініціює процедуру *AODV Route Discovery* та автоматично перемикає маршрут на резервний шлях через `Router 1`. Після відновлення живлення `Router 2` топологія автоматично повертається до оптимального стану `HEALTHY`.

## 3. Інтеграційний порівняльний аналіз протоколів

У файлі `cross_protocol_analytics.rules` реалізовано автоматичний збір метрик та порівняння характеристик LPWAN і Mesh у реальному часі:

1. **Енергоефективність:** Пристрої LoRaWAN демонструють значно менший розряд батареї в перерахунку на тривалість життєвого циклу завдяки відсутності необхідності ретранслювати чужий трафік. У Zigbee роутери вимагають стаціонарного живлення, а кінцеві пристрої витрачають заряд швидше через частіші сеанси зв'язку.
2. **Дальність покриття vs Пропускна здатність:** LoRaWAN забезпечує покриття до **14.2–15 км** від одного шлюзу за рахунок модуляції CSS, але має низьку швидкість передачі та обмеження `Duty Cycle < 1%`. Zigbee покриває локальні зони, проте масштабується через багатоступеневу ретрансляцію і забезпечує низьку затримку ~15мс.
3. **Надійність та відмовостійкість:** У LoRaWAN надійність забезпечується одночасною доставкою пакету на декілька шлюзів та алгоритмом **ADR**. У Zigbee відмовостійкість гарантується динамічною маршрутизацією **AODV Self-Healing** в обхід пошкоджених роутерів.
